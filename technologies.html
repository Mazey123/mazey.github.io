Технологии

Из чего состоит прогрессивное веб-приложение

PWA не требует нового языка программирования — она строится на нескольких браузерных API, работающих поверх обычных HTML, CSS и JavaScript. Ниже — четыре технологии, без которых сайт не сможет называться прогрессивным веб-приложением.

Service Worker

Фоновый скрипт, который браузер запускает отдельно от страницы. Он перехватывает сетевые запросы, решает — отдать ответ из кэша или сходить в сеть, — и продолжает работать, даже когда вкладка с сайтом закрыта. Именно Service Worker отвечает за офлайн-режим и фоновую синхронизацию.

Web App Manifest

JSON-файл с описанием приложения: название, иконки разных размеров, основной цвет темы, ориентация экрана и стартовый URL. Именно манифест сообщает браузеру, что сайт можно «установить», и как будет выглядеть его значок на рабочем столе.

Cache API и стратегии кэширования

Программный интерфейс для хранения пар «запрос → ответ» на устройстве пользователя. Service Worker использует Cache API, чтобы решить, какую стратегию применить: «сначала кэш», «сначала сеть» или «сеть с резервным кэшем» — в зависимости от типа контента.

Push API и Notifications API

Позволяют серверу присылать уведомления пользователю, даже если сайт в этот момент не открыт в браузере — так же, как это делают нативные приложения. Требуют явного разрешения пользователя и защищённого соединения HTTPS.

Поддержка в браузерах

Не все технологии одинаково поддерживаются во всех браузерах — это стоит учитывать при проектировании PWA, чтобы сайт «прогрессивно» улучшался там, где API доступен, и оставался рабочим там, где его нет.

Глоссарий терминов

  • App Shell — минимальный HTML/CSS/JS каркас интерфейса
  • HTTPS — обязательное защищённое соединение для PWA
  • Manifest — файл настроек установки приложения
  • Offline-first — подход «сначала офлайн, затем сеть»
  • Lighthouse — инструмент аудита качества PWA
