Архитектура

Модель App Shell

Большинство PWA строится по модели App Shell — «каркаса приложения». Идея в том, чтобы разделить интерфейс на две части: редко меняющийся каркас (шапка, меню, разметка экрана) и часто обновляемый контент (тексты, изображения, данные). Каркас кэшируется Service Worker'ом при первом посещении и мгновенно отрисовывается при каждом следующем открытии, пока актуальный контент подгружается из сети.

Такое разделение даёт два эффекта: во-первых, пользователь почти сразу видит знакомый интерфейс вместо белого экрана загрузки; во-вторых, приложение способно показать хотя бы каркас и последние закэшированные данные, даже если сеть недоступна.

PWA, нативное приложение или обычный сайт?

Выбор архитектуры зависит от задач проекта. Таблица ниже сравнивает три подхода по ключевым для бизнеса и разработки параметрам.

Сравнение прогрессивного веб-приложения, нативного приложения и классического сайта
Параметр PWA Нативное приложение Обычный сайт
Установка на устройство Да, из браузера Да, из магазина Нет
Работа офлайн Частично, через кэш Полностью Нет
Push-уведомления Да (с оговорками для iOS) Да Нет
Обновление версии Автоматически, без модерации Через магазин приложений Автоматически
Индексация поисковиками Да Нет Да
Стоимость разработки Одна кодовая база Отдельно под iOS и Android Одна кодовая база
Доступ к API устройства Ограниченный Полный Минимальный
